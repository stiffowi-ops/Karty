# Karty 2.18.0 — личный кабинет и обращения

## Для клиента

Главное меню → **👤 Личный кабинет**. Здесь доступны текущее обращение, незавершённая анкета/дополнение, решённые обращения и история всех обращений.

| Статус | Значение | Действия |
| --- | --- | --- |
| Получено | Обращение сохранено и ожидает специалиста | Добавить локации, написать уточнение |
| В работе | Администратор назначен ответственным | Добавить локации, написать уточнение |
| Решено | Специалист явно завершил обращение и указал итог | Читать итог и историю, создать новое обращение |

Одно активное обращение сохраняется до завершения. Кнопка заявки из карточки другой точки предлагает добавить её к текущему обращению. Можно выбрать несколько локаций, добавить комментарий, проверить пакет и нажать **«Отправить дополнение»**. Отмеченные точки и набранный текст до подтверждения не отправляются администраторам.

За один пакет можно добавить до 10 новых локаций, всего в обращении — до 20. Комментарий — до 1000 символов. Уже выбранная точка повторно не добавляется. Повторное нажатие отправки не создаёт новое дополнение.

При выходе в другие разделы черновики сохраняются на паузе. Возобновление — через кабинет или кнопку **«Продолжить»**. После перезапуска они также требуют явного возобновления. При создании следующего обращения клиент подтверждает прежние контактные данные либо заполняет анкету заново. Проверка российского телефона остаётся прежней: `+7` и 10 цифр.

Клиент получает отдельные сообщения, когда обращение принято в работу, специалист принял конкретное дополнение и обращение решено с итогом. Вся история доступна в кабинете, только владельцу Telegram-аккаунта.

## Для администратора

Админ-панель → **Заявки** → карточка обращения. Список разбит на страницы; карточка содержит контакты, все локации, ответственного, статус и полную историю.

1. Нажмите **«Взять в работу»**. Ответственным становится первый нажавший администратор. Другие администраторы по-прежнему имеют доступ к карточке.
2. При дополнении приходит **новое сообщение** с номером заявки и дополнения, новыми локациями и комментарием. До назначения ответственного сообщение получают все `ADMIN_IDS`, затем — только ответственный. Если его ID больше нет среди администраторов, уведомление получают все текущие администраторы.
3. Нажмите **«Принять дополнение»** в аларме или карточке. Клиент увидит принятие; каждое дополнение подтверждается отдельно. Повторный клик не меняет ранее записанного автора и времени принятия.
4. Для завершения нажмите **«Решить обращение»**, напишите итог и подтвердите его на экране проверки. Итог увидит клиент. Перед завершением нужно принять все отправленные дополнения. Если новое дополнение поступило во время подготовки итога, завершение блокируется до повторной проверки.

Основные уведомления с заявкой обновляются у всех администраторов. Скрывать и удалять можно только решённые обращения. Если в корзине осталась старая незавершённая заявка, сначала восстановите её для обработки.

## Напоминания и доставка

- Через **2 часа после отправки непринятого дополнения** — одно напоминание ответственному; если он ещё не назначен — всем администраторам.
- Через **4 часа** — однократная эскалация остальным администраторам. Без ответственного эскалацию получают все.
- Это фактически прошедшие часы, включая вечер, выходные и время остановки бота. Рабочий календарь не задан. Проверка выполняется раз в минуту.
- После принятия дополнения или решения обращения напоминания по нему прекращаются.
- Подтверждения успешной доставки сохраняются отдельно для события, этапа и получателя. После перезапуска уже подтверждённая доставка не повторяется, ошибки повторяются. Как и у прежних уведомлений, у Telegram нет транзакции с локальным файлом: авария между фактической отправкой и записью подтверждения может привести к повторному сообщению.

Срок ответа специалиста клиенту автоматически не обещается.

## Данные и обновление

Новые поля хранятся в прежнем `DATA_DIR/leads.json`; нужны постоянный Docker volume и существующий `ADMIN_IDS`. Новых зависимостей и переменных окружения нет. Старые контакты, номера, избранное и заявки сохраняются. Прежний статус «Взято в работу» остаётся «В работе», исторические записи доступны в общей истории; они не становятся решёнными автоматически.

Перед обновлением сохраните резервную копию runtime/volume. После включения изменения в основную ветку обновите существующую установку из каталога репозитория:

```bash
git pull --ff-only origin main
docker compose up -d --build --force-recreate
```

ZIP-восстановление сохраняет более новые статусы, историю и подтверждения доставки. Уже отправленный токен дополнения не возвращается в черновики. При откате на старую версию используйте соответствующую резервную копию runtime: прежний код не поддерживает новые поля сопровождения.

## Проверки

```bash
go test ./...
go test -race ./...
go vet ./...
go build ./...
python3 -m unittest discover -s scripts -p 'test_*.py'
```

Тесты используют подменённый Telegram-транспорт: проверяются доступ к личным данным, группировка дополнений, идемпотентность, конкурентные действия, маршрутизация и повтор доставки, напоминания, история, пауза форм и ZIP-восстановление. Перед эксплуатацией проверьте полный путь клиент → администратор на рабочем Telegram-боте.

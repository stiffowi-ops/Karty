# Karty · Telegram-бот на Go · версия 2.18.0

**В версии 2.13.0 админка обновлена и проверяется перед публикацией в GitHub.**

## v2.18.0 · Личный кабинет и сопровождение обращений

- В главном меню добавлен «👤 Личный кабинет»: активное обращение, статусы «Получено», «В работе», «Решено», решённые обращения и полная история.
- Одно активное обращение на клиента действует до явного завершения с итогом. Принятие в работу больше не открывает повторную анкету. Из карточки другой локации можно добавить её к текущему обращению.
- Дополнение объединяет до 10 новых локаций и комментарий до 1000 символов; в обращении можно обсудить до 20 локаций. Отправка подтверждается клиентом один раз.
- До назначения ответственного новое дополнение получают все `ADMIN_IDS`, после назначения — ответственный. Основные карточки администраторов обновляются. Принятие каждого дополнения подтверждается отдельно.
- Клиент получает уведомления о принятии обращения в работу, принятии дополнения и завершении с итогом. Состояние и подтверждения доставки сохраняются в `leads.json`.
- Непринятое дополнение вызывает одно напоминание через 2 часа ответственному, через 4 часа — остальным администраторам; без назначенного ответственного получатели — все администраторы. Это фактически прошедшее время, без календаря рабочих часов. Проверка и повтор ошибок доставки выполняются раз в минуту.
- Черновики сохраняются, при выходе в другие разделы ставятся на паузу; после перезапуска нужно нажать «Продолжить». Поиск больше не записывает название локации в поля незавершённой анкеты.
- Новое обращение после завершения предлагает подтвердить предыдущие контактные данные. История не перезаписывается. Старые записи «Взято в работу» не объявляются решёнными автоматически.
- Активное обращение нельзя скрыть или удалить: сначала нужно завершить его с итогом. Старую скрытую запись при необходимости сначала восстановите из корзины.
- ZIP-бэкапы включают новые поля, историю дополнений и черновики; восстановление сохраняет актуальные статусы и подтверждения доставки. Старый ZIP не возвращает уже отправленное дополнение в черновики.

Сценарии и установка: [CLIENT_CABINET.md](CLIENT_CABINET.md). Новых переменных окружения и Mini App не требуется. Разделы ниже описывают прежние версии; для обработки обращений приоритет имеет этот раздел.

## Каталог на 114 локаций (v2.6.1)

В приложение включены **114 уникальных локаций** и все 114 структурированных описаний из Excel от 16.11.2026: линия/статус, ориентир, трафик, аудитория, возможности, итог. Повторы «Дзержинский» и «Подрезково» исключены; для Дзержинского использована более подробная запись. Название локации в сообщении выделяется жирным. Служебный заголовок «КОПИРКА · КАРТА ЛОКАЦИЙ ДЛЯ ПАРТНЁРОВ» удалён.

Основной полный каталог и описания лежат в `internal/catalog/bundled_seed.json.gz` и `internal/catalog/bundled_partner_cards.json.gz`. Это сжатые JSON-файлы, автоматически встроенные в Go-приложение: разархивировать на сервере не требуется. Для просмотра их можно распаковать стандартным gzip. `config/seed.json` остаётся старым резервным списком первых 40 точек, но при запуске реальный каталог автоматически дополняется до 114. Новые точки видны в /list и поиске. Картинки и координаты не выдумываются. Заполненные пользовательские поля из `config/overrides.json` и текущего каталога сохраняют приоритет.

В `config/partner_cards.json` оставлен пустой объект `{}`: локальные правки и новые карточки можно добавлять там, при этом они перекрывают встроенные данные по ID, а `config/overrides.json` имеет наивысший приоритет. При обновлении сервера **пересоберите Docker** (`docker compose up -d --build --force-recreate`), потому что данные встроены в бинарник.

## Что увидит пользователь

Обычный Telegram-бот, без Mini App. При выборе локации он отправляет **одно текстовое сообщение** с партнёрской карточкой, кнопками навигации и ссылкой **«Открыть карту»**. Фотографии временно отключены. Если для локации нет своих координат или ссылки, кнопка открывает общую карту проекта.

### Структура каждой карточки

- 🚇 Название локации
- **КОПИРКА · КАРТА ЛОКАЦИЙ ДЛЯ ПАРТНЁРОВ**
- Линия и статус (если данные известны; иначе нейтральная заглушка)
- **Ориентир** (если известен)
- **1. ТРАФИК И ЛОКАЦИЯ**
- **2. КТО ПЛАТИТ**
- **3. ОКНО ВОЗМОЖНОСТЕЙ**
- **4. ИТОГ: ПОЧЕМУ ИМЕННО ЗДЕСЬ**
- **Оценка**, только если она заполнена
- **Локация на карте**: ссылка «Открыть карту»; при отсутствии `map_url` и координат открывается общая карта проекта

Весь текст новых карточек перенесён из Excel в комплект поставки; незаполненных шаблонов больше нет.

Текст «Бирюлёвская линия · открыто» воспроизведён как предоставленный пользователем материал; актуальность транспортных фактов независимо не проверялась.

## Где редактировать текст

- `config/partner_cards.json` — необязательные локальные дополнения/переопределения карточек по ID; базовые 114 описаний встроены в приложение.
- `config/overrides.json` — **твои собственные переопределения**: координаты, рейтинги, уточнения текста. Этот файл не очищаем при обновлениях; он имеет приоритет над `partner_cards.json`.
- `config/overrides.example.json` — пример структуры для заполнения всех объектов.

Пример одного блока в `config/partner_cards.json` или `config/overrides.json`:

```json
{
  "002": {
    "line_status": "Бирюлёвская линия · открыто",
    "landmarks": "Нагатино-Садовники",
    "traffic": "Действующая станция: пассажиропоток идёт уже сегодня, ждать пуска не нужно.",
    "payers": "Жители Нагатино-Садовников: срочная печать, копии, документы.",
    "opportunity": "Окно открыто прямо сейчас — старт выручки с первого месяца работы.",
    "conclusion": "Единственная точка у работающей станции — старт без периода ожида…"
  }
}
```

Незаполненное поле отображается как «Информация пока не добавлена». Если в старой конфигурации уже было обычное `description`, оно временно отображается в первом разделе, пока не будет перенесено в поле `traffic`.

## Индивидуальные точки Яндекс Карт · 104 локации (v2.6.4)

Из проверенного экспорта Конструктора Яндекс Карт встроены **104 координаты** (`internal/catalog/bundled_geo_104.csv`). При открытии карточки ссылка **«Открыть карту»** ведёт на **одну конкретную точку** (`ll`, `pt`, `z=17`), а не на общий слой карты. Бот использует соответствие по стабильным ID утверждённых 114 локаций и не меняет их названия, описания и избранное. Сохранённая в Docker volume ссылка-заглушка для одной из 104 подтверждённых точек заменяется индивидуальной; `config/overrides.json` по-прежнему может явно изменить координаты и URL.

**Без подтверждённой геопозиции** пока остаются 10 локаций:
- 8 без координат в экспорте: **006 Метро Каспийская**, **007 Метро Липецкая** (не путать с 061 «Липецкая»), **010 Метро Народное Ополчение**, **011 Метро Липовая Роща**, **030 Метро Верейская**, **035 МГСУ**, **051 Калитники**, **052 Текстильщики-2**.
- 2 сомнительных совпадения: **054 Депо/Пререва ↔ Депо / Перерва** и **065 Москва, бульвар Дмитрия Донского ↔ Бульвар Дмитрия Донского 2**.

Для них автоматически НЕ назначаются координаты. При отсутствии старой подтверждённой индивидуальной ссылки карта остаётся общей до ручного уточнения. При последующей синхронизации фотографий встроенные координаты 104 точек сохраняются; дополнительные координаты можно явно задавать через `config/overrides.json`.

## Геопозиция на компьютере: текущий статус

В v2.7.3 из сообщения «Рядом со мной» убран технический текст. Пока бот принимает геопозицию, отправленную как Telegram Location (обычно доступно на мобильном клиенте). Telegram Desktop не всегда поддерживает нативный выбор/отправку локации. Отдельный выбор точки на интерактивной карте или обработка ссылок Яндекс Карт **только предложены**, в код ещё не внедрялись.

## Поиск ближайших точек по ссылке Яндекс Карт (v2.7.4)

В разделе **«📍 Рядом со мной»** добавлен краткий гайд для ПК и кнопка **«🗺 Открыть Яндекс Карты»**. Пользователь выбирает место на карте, открывает «Что здесь?» и «Поделиться», копирует ссылку и отправляет её боту. Если ссылка содержит координаты (параметры `whatshere[point]`, `pt`, `ll`) или является короткой ссылкой с перенаправлением на координаты, бот показывает 5 ближайших локаций из каталога.

Если ссылка не содержит точного положения, бот не угадывает координаты и предлагает скопировать их в Яндекс Картах, например `55.751, 37.618`, и отправить в чат. С коротких ссылок разрешаются до 4 перенаправлений по разрешённым адресам Яндекс Карт. Обычный поиск по названию остаётся прежним.

### Проверка телефона и заголовок заявки (v2.10.1)

Телефон в анкете принимается только в российском формате **`+7` + ровно 10 цифр**. Допускаются пробелы, дефисы и скобки, которые при сохранении удаляются. Например, `+7 (906) 528-89-35` сохраняется как `+79065288935`. Неполные, избыточные и иные международные номера не принимаются; при ошибке бот просит ввести номер ещё раз. Уведомление администраторам начинается с **«📨 Заявка №0001»** без упоминания Karty.

## v2.17.0 · Управление удалением заявок и посетителей

**В админке** разделы «📨 Заявки» и «👥 Посетители» содержат кнопки «🗑 Выбрать» и «♻️ Корзина». Доступны поштучный выбор, выбор всех записей на текущей странице, выбор нескольких записей через разные страницы, подтверждение операции, восстановление из корзины и необратимое удаление из рабочего хранилища. Работа с данными проверяется на сервере по `ADMIN_IDS` при каждом действии.

- Скрытие записи не удаляет её с диска, но исключает из списка администратора и из сводных показателей; она остаётся в корзине, откуда её можно восстановить.
- Необработанные заявки нельзя скрыть или удалить: сначала нажмите «📥 Взять в работу». Нумерация заявок после удаления не сбрасывается и никогда не повторяется.
- Скрытый посетитель не вызывает новые уведомления. При окончательном удалении сохраняется только служебный Telegram ID, дата удаления, чтобы по тому же пользователю не возник новый аларм после следующего `/start`.
- При окончательном удалении заявки сохраняется только её номер и дата удаления. **Технические отметки** `runtime/deletion_ledger.json` защищают от возврата старых данных при восстановлении ZIP. Сам файл включается в новые резервные копии. Файлы `leads.json` и `visitors.json` после полного удаления больше не содержат запись.
- Окончательное удаление **не** стирает уже отправленные сообщения Telegram и старые ZIP-файлы; такие архивы нужно очищать отдельно в соответствии с правилами хранения данных.
- Новых команд Telegram нет: пользователь по-прежнему видит только `/start`.

## v2.16.0 · Посетители без заявки

В админке доступен раздел **«👥 Посетители»** с вкладками «Без заявки» и «Все посетители». Для каждого пользователя Telegram, который взаимодействовал с ботом в личном чате, сохраняются доступные имя, фамилия, username, Telegram ID, первая и последняя активности, первый маршрут по разделам и дневной счётчик визитов. Телефон Telegram API не предоставляет; контактный номер сюда не добавляется.

- **Один первый маршрут:** разделы фиксируются с временем до начала второй сессии, не сохраняются текстовые запросы, телефоны, геопозиция или другие свободно введённые данные. История первого маршрута удаляется через 30 дней, ежедневные счётчики — через 35 дней. Факт посещения и маркер отправленного алерта сохраняются, чтобы не слать повторные уведомления.
- **Посещения:** новый визит считается, если предыдущей активности не было 30 минут, либо пользователь вновь вызвал `/start` и с предыдущего `/start` прошло хотя бы 5 минут. Каждое нажатие кнопки не является новым визитом. Дни считаются по московскому времени (МСК, UTC+3).
- **Алерт:** через 60 минут после первого наблюдаемого действия без зарегистрированной заявки администраторы из `ADMIN_IDS` получают однократную сводку с именем, ником, ID, датами, первым маршрутом и кнопкой профиля. Если заявка подана до проверки или была подана раньше, уведомление не отправляется. В случае поздней заявки карточка в аналитике переключается на «Заявка получена».
- **Ограничения Telegram:** бот не узнаёт о пассивном открытии или закрытии чата, о скрытом номере телефона, о действиях вне бота; отчёт показывает только зафиксированную активность. Ссылка на профиль работает, только если Telegram разрешает открыть пользователя.
- **Устойчивость:** хранение в `runtime/visitors.json`, атомарная запись и загрузка после перезапуска. Файл добавлен к новым ZIP-бэкапам; восстановление не сбрасывает флаг отправленных уведомлений или более новые посещения.
- Для защиты персональных данных статистика доступна только администраторам и хранится на сервере. Перед реальным использованием актуализируйте уведомление о сборе данных в боте и правила обработки персональных данных.

## v2.15.0 · Обработка заявок администратором

- Во всех заголовках внутри интерфейса админки убраны технические обозначения проекта: «Система», «Резервные копии», «Заявки». Техническое имя проекта, ID inline-поиска и название репозитория не меняются.
- Форма клиента остаётся прежней. При подаче новой заявки администраторы получают уведомление с кнопкой «📥 Взять в работу». До первого нажатия повторная подача заблокирована.
- После принятия заявки в работу она сохраняется со статусом «✅ Взято в работу», идентификатором администратора и временем; кнопка становится зелёной (`style: success`, поддерживается актуальными клиентами Telegram). Бот пытается обновить известные копии уведомления у всех `ADMIN_IDS`.
- Пользователь получает возможность отправить очередную заявку только после перехода предыдущей в работу. Новая заявка получает следующий последовательный номер, ранее обработанные обращения навсегда остаются в истории.
- Старые уведомления без кнопки обрабатываются из админ-раздела «📨 Заявки». Любой повторный клик или параллельное принятие уже обработанной заявки не создаёт дубликатов.
- `leads.json` совместим со старой структурой, дополнен необязательным массивом `history` и метаданными статуса. При восстановлении из ZIP сохраняются более новые заявки и их статусы, включая ранее обработанные.
- Бэкап ZIP и статистика заявок учитывают всю историю, а не только последнее обращение пользователя.

## Karty v2.14.0 · Удобство админ-редактора и новые локации

- **Редактирование полей:** при выборе названия, статуса, ориентира, ссылки карты, краткого описания, категории, заголовка и текста раздела администратор видит текущее значение перед вводом нового. Пустое поле обозначено как «Не заполнено». Значения выводятся с HTML-экранированием.
- **Два столбца:** список локаций и найденные результаты администраторского поиска показываются попарно, как в пользовательском каталоге.
- **Добавление локации прямо в Telegram:** кнопка «➕ Добавить локацию» запускает черновик, в который можно внести название, статус, ориентир, ссылку карты, описание, категорию и до 15 произвольных разделов. Можно посмотреть предпросмотр и отменить создание. Пока не нажата «✅ Добавить локацию», публичный каталог не меняется. ID создаётся автоматически, сохраняется и не зависит от текста названия.
- **Постоянное хранение:** администраторские локации записываются атомарно в `runtime/admin_locations.json` отдельно от встроенных 114 точек, чтобы обновление приложения и синхронизация Яндекс Диска их не удаляли.
- **Резервные копии:** `admin_locations.json` включён в новые ZIP-бэкапы. При восстановлении новые архивы возвращают добавленные локации, старые архивы сохраняют те дополнительные локации, которые появились позднее. Существующие заявки и избранное остаются под защитой ранее реализованного объединения.
- **Панель управления:** на главном экране нет слова Karty в заголовке, статистических чисел и счётчиков. Вместо них короткое описание возможностей раздела.

## Заявки на сотрудничество (v2.10.0)

Кнопка **«📝 Оставить заявку»** доступна в главном меню **над «📍 Рядом со мной»**, а также в каталоге, избранном, поиске и карточках локаций. Все тексты анкеты обращаются к клиенту **на «Вы»**.

**Сценарии:**
- **«🤝 Уже работаю с Вами»** → имя → номер телефона → выбор локации → проверка данных → отправка.
- **«🚀 Хочу работать с Вами»** → наименование юридического лица → имя → номер телефона → выбор локации → проверка данных → отправка.

При открытии из главного меню клиент выбирает из полного каталога (114 локаций), из раздела **«Избранное»** — только из своих сохранённых точек; при открытии из карточки предлагается подтвердить конкретную локацию или сменить её. Внутри анкеты можно выбрать из постраничного списка либо найти точку по части названия. Из inline-карточек форма открывается **только в личном чате** пользователя.

Клиент проверяет данные перед отправкой. Черновик сохраняется на диске. После успешного сохранения действует **одна заявка на Telegram ID**: повторные нажатия и повторные попытки не создают новые заявки. Для первой и повторной отправки предусмотрены вежливые сообщения. Это ограничение по аккаунту, а не гарантия уникальности физического человека.

Все заявки сохраняются в **`DATA_DIR/leads.json`** (Docker volume, права 0600), отдельно от избранного и каталога. Записи не удаляются при перезапуске. **Всем администраторам из существующего `ADMIN_IDS`** отправляется одинаковая копия заявки с типом клиента, юрлицом (если указано), именем, телефоном, локацией, Telegram ID и источником обращения. Новая переменная не требуется. Уведомления отправляются каждому администратору отдельно; недоставленные копии повторяются после перезапуска и периодически. Список заявок доступен администраторам по команде `/applications`.

**Где добавить администраторов:** в существующем серверном файле `.env` рядом с `docker-compose.yml`:

```env
ADMIN_IDS=123456789,987654321,555666777
```

Замените эти примерные номера настоящими Telegram ID администраторов, через запятую. Каждый администратор должен хотя бы раз открыть бота и отправить `/start`, иначе Telegram не позволит написать ему первым. После изменения `.env` выполните `docker compose up -d --force-recreate`. Реальные ID, контактные данные, заявки и `.env` нельзя публиковать в GitHub.

## Раскрывающиеся карточки Rich Messages (v2.9.0)

Начиная с Bot API 10.1, Telegram поддерживает **Rich Messages** с `<details><summary>...` для сворачиваемых секций. Для обычных карточек Karty используется `sendRichMessage`, для переходов по кнопкам `editMessageText` c `rich_message`, а для живого поиска `InputRichMessageContent`.

В карточках четыре закрытых блока: «Трафик и локация», «Кто платит», «Возможности для бизнеса», «Почему именно здесь». Название, статус, ориентир и **индивидуальная ссылка на карту** остаются видны всегда. Никаких фотографий. Текст экранируется, проверенные ссылки сохраняются.

Кнопки карточки: «⭐ Добавить в избранное» / «✅ Убрать из избранного» (динамическое состояние), «⭐ Перейти в избранное», «🏠 Главное меню», «🔎 Поиск локации». В inline-результатах **убрана отдельная кнопка открытия карты**: ссылка уже есть в карточке. После сохранения inline-результата бот пытается обновить подпись кнопки через `editMessageReplyMarkup` по `inline_message_id`; избранное хранится отдельно для каждого пользователя. Если inline-карточка опубликована в общем чате, сменившееся название кнопки может отображаться всем участникам, но **содержимое личного избранного туда не отправляется**. Переходы из inline-карточек отправляют соответствующее меню в личный чат нажавшего пользователя.

Для старых Telegram-клиентов отображение Rich Messages зависит от поддержки со стороны приложения. Обычные разделы меню продолжают работать с текстовыми сообщениями.

## Аккуратные текстовые карточки в стиле tg-work-bot (v2.8.1)

## Единый экран и карточки без служебных пометок (v2.8.0)

- В пользовательских карточках, списках, inline-подсказках и сравнении скрывается служебная пометка `(данные проверить)`. В исходных JSON-файлах и переопределениях она остаётся для проверки менеджером; это не подтверждает достоверность адреса.
- При выборе результата живого inline-поиска Telegram присылает сообщение с полем `via_bot`. Бот не пытается повторно искать по полному тексту такой готовой карточки, поэтому не пишет «Ничего не найдено».
- При переходах по **inline-кнопкам сообщений бота** применяется `editMessageText`: список, карточка, избранное, сравнение и главное меню заменяют текущее сообщение, не добавляя новый пузырь. Если сообщение нельзя изменить (старое, недоступное или принадлежит пользователю), бот отправляет отдельное новое сообщение, сохраняя работоспособность.
- **Не удаляем пользовательские сообщения.** Карточка, которую пользователь отправил через Inline Mode, не является обычным сообщением бота; она остаётся в истории. Уборка старых сообщений «задним числом» не предусмотрена.
- Новые /start и прямые команды могут создавать отдельное сообщение. Это безопаснее массового удаления истории и не затрагивает избранное.

## Живой поиск с подсказками Telegram (v2.7.0)

Для кнопки **«🔎 Поиск локации»** используется нативный **Telegram Inline Mode** вместо ожидания отправки сообщения. В BotFather для бота нужно включить **/setinline** (это делается один раз). Кнопка вызывает `switch_inline_query_current_chat`, и Telegram открывает inline-поле поиска в текущем чате; при вводе каждого символа появляются подходящие названия из утверждённых 114 локаций.

Выдача состоит только из названий каталога, без совпадений по случайным словам из описаний. Поиск не зависит от регистра и «е/ё», понимает названия без «Метро», сортирует сначала совпадения с начала названия, затем слова и подстроки. Отображается до 15 подсказок. При выборе Telegram отправляет полную текстовую карточку локации с ссылкой на конкретную точку Яндекс Карт (если подтверждена), кнопками карты, избранного и повторного inline-поиска.

**Избранное:** из inline-карточки его можно добавить/удалить специальной кнопкой; запись относится к Telegram ID нажавшего пользователя, а не к владельцу сообщения или чату. Telegram сообщает об успехе всплывающим уведомлением. Текст и кнопка избранного не обязаны менять состояние в общей карточке, т.к. inline-сообщения могут пересылаться/показываться другим пользователям. Обычная карточка с избранным и команды `/favorites` продолжают работать.

При открытии старых сообщений кнопки с callback `search` сохраняют совместимость: бот показывает сообщение-подсказку с новой кнопкой inline-поиска. Обычный поиск отправкой названия также продолжает работать. Подключать DaData или другой сторонний сервис не нужно. Данные пользователя и каталог не изменяются.

## Навигация

Число локаций в приветствии `/start` и в описании `/list` больше не выводится; сами каталоги по-прежнему содержат утверждённые 114 точек. В режиме `NewWithBundled` видны **только 114 утверждённых ID**; лишние и дублированные записи из старого `catalog.json` или синхронизации Яндекс Диска не выводятся. Исходный сохранённый файл в Docker volume не удаляется, а существующие поля, координаты и изображения утверждённых ID используются как прежде. Обобщённые подписи, поиск, избранное и сравнение говорят «локация» вместо «станция»; названия конкретных станций метро не меняются.

После `/start` бот персонально приветствует пользователя и показывает слоган **«Не просто точки на карте. Точки роста твоего бизнеса!»**. В тексте говорится о списке бизнес-локаций, преимуществах, сравнении и сохранении в избранное, без числового счётчика.


Команда `/start` здоровается по имени и фамилии из Telegram. Под приветствием — **только inline-кнопки**, три ряда: «📋 Список локаций» и «🗺 Карта локаций» (прямая ссылка), «⭐ Избранное» и «🔎 Поиск локации» (живые подсказки), внизу на всю ширину «📍 Рядом со мной». При нажатии «Рядом со мной» бот предлагает вручную отправить геопозицию через **скрепку Telegram → Геопозиция → Отправить текущую геопозицию**; после получения координат показывает ближайшие точки. Telegram **не поддерживает** автоматический запрос координат через inline-кнопку, поэтому нативной кнопки `request_location` больше нет. При /start и переходе в поиск ближайших бот убирает старую постоянную reply-клавиатуру предыдущих версий, чтобы под строкой ввода не появлялись зелёные кнопки. Избранное, живой поиск, сравнение и прямые ссылки на карте работают как прежде.

В карточке локации есть кнопка **«⭐ Добавить в избранное»** / **«✅ Убрать из избранного»**. Список избранного хранится отдельно для каждого Telegram ID в `DATA_DIR/favorites.json`, который находится в Docker volume и сохраняется при пересборке контейнера. Для пустого списка показываются быстрые переходы к списку локаций и поиску. Из раздела избранного можно выбрать **2–3 локации** для сравнения по линии и статусу, ориентиру, трафику, аудитории, возможностям и итогу. Сама информация берётся из карточек; незаполненные поля отмечаются как незаполненные.

В списке `/list` бот показывает дружелюбное приветствие «📍 Каталог локаций» без числа точек, с подсказкой про избранное и номером страницы. Сами кнопки: **алфавит от А до Я, две в строке**, десять локаций на страницу. Из карточки: строка **«⬅️ К списку» · «🔎 Поиск локации»**, под ней **«🏠 Главное меню»**. При возврате в каталог сохраняется предыдущая страница. Поиск по названию работает; геопоиск ближайших локаций требует координат объектов.

Новая схема в v2.7.2: кнопка «Рядом со мной» — inline, Telegram не умеет выдавать геопозицию напрямую через такую кнопку. Пользователь нажимает скрепку, выбирает «Геопозиция» и отправляет текущую точку. Сообщения с координатами по-прежнему обрабатываются ботом. Нативная reply-клавиатура из v2.7.1 удалена.

Для поиска ближайшей локации по геопозиции нужен экспорт исходной карты из Конструктора Яндекс Карт. Публичная ссылка на слой пока не предоставила машиночитаемых координат. Бот не придумывает положение локации; карточка без координат ведёт на общую карту проекта.

Когда получен экспорт GeoJSON/CSV, можно запустить просмотр совпадений:

```bash
python3 scripts/import_coords.py map.geojson
```

Если сопоставление однозначно и проверено:

```bash
python3 scripts/import_coords.py map.geojson --write
```

Скрипт добавит координаты в `config/overrides.json`, **сохранив** остальные поля. Внутри бота администратор выполняет `/reload`; затем `/status` показывает, сколько локаций имеют координаты. **Новая переменная окружения для координат не нужна.**

Индивидуальный `map_url` из карты владельца можно записать в `config/overrides.json`; если его нет, подтверждённые координаты добавляются к ссылке проекта. Пока координаты и индивидуальная ссылка отсутствуют, используется общая карта проекта.

## Обновление сервера

Твои `.env` и данные в Docker volume должны остаться на сервере. Не загружай настоящий `.env` или токен в GitHub.

```bash
# После обновления исходников в GitHub выполни:
cd /path/to/Karty
git pull --ff-only
docker compose up -d --build
```

Если изменял `config/overrides.json` **локально на сервере**, перед `git pull` обязательно сохрани его копию и проверь, нет ли конфликта изменений. Файл `partner_cards.json` добавлен отдельно именно для того, чтобы не перезаписывать пользовательские данные.

В боте команды: `/start`, `/list`, `/favorites`, `/compare`, `/near`, `/map`, `/id`; администратору доступны `/sync` (Яндекс Диск), `/reload` (перечитать JSON), `/status`.

Пример `.env` уже в репозитории: `BOT_TOKEN`, `ADMIN_IDS`, `MAP_CONSTRUCTOR_ID`, `YANDEX_DISK_PUBLIC_URL`, `SYNC_ON_START=true`, `SYNC_INTERVAL=12h`, `DATA_DIR`, `OVERRIDES_PATH`. **Новых переменных не требуется**.
